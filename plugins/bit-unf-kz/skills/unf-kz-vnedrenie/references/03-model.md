# Модель в демобазе: рабочее место, порядок, ловушки

Модель строится только в своей копии демобазы. Клиентские базы и чужие демобазы без разрешения не трогаем.

## Рабочее место
1. **Дистрибутив** УНФ KZ нужного релиза — с releases.1c.ru. После установки в каталоге шаблонов лежат `1Cv8.cf` (пустая конфигурация) и `1Cv8.dt` (демобаза).
2. **Демобаза** (файловая — проще всего):
   ```
   "C:\Program Files\1cv8\<версия>\bin\1cv8.exe" CREATEINFOBASE File="C:\Bases\unf_demo"
   "C:\Program Files\1cv8\<версия>\bin\1cv8.exe" DESIGNER /F "C:\Bases\unf_demo" /RestoreIB "<шаблоны>\1Cv8.dt"
   ```
   Чистую демобазу оставляем как эталон. **Модель** — отдельная база (`unf_model`), развёрнутая из того же dt; новая модель под нового клиента — снова из dt.
3. **Выгрузка конфигурации в XML** — для проверки по коду (долго, несколько ГБ):
   ```
   "...\1cv8.exe" DESIGNER /F "C:\Bases\unf_demo" /N "Администратор" /DumpConfigToFiles "C:\Work\unf_xml" /Out dump.log
   ```
   Если у пользователя ИБ есть пароль — добавить `/P "<пароль>"`. Без `/N` выгрузка падает с «Пользователь ИБ не идентифицирован».
4. **Запуск кода** в базе — `scripts/run-code.ps1` (рядом `ВыполнитьКодИзФайла.epf`):
   ```
   powershell -ExecutionPolicy Bypass -File run-code.ps1 -CodeFile C:\Work\client\model\10-nsi.bsl -FileBase "C:\Bases\unf_model" -User Администратор
   ```
   Серверная база — `-Server <сервер> -Base <имя>`, и версия клиента должна совпадать с версией сервера 1С (`-Platform` с путём к нужному `1cv8c.exe`), иначе запуск молча завершается без результата.
   Если при запуске появляется окно «Предупреждение безопасности» — в `conf.cfg` платформы нужна строка `DisableUnsafeActionProtection=.*` (согласовать с владельцем компьютера).

## Как писать код модели
- Итог — в переменную `Результат`; процедуры и функции объявлять нельзя (код выполняется через `Выполнить`).
- Каждый шаг — в своей `Попытка … Исключение`: отказ проведения — это результат проверки, его пишем в лог.
- После шагов — `ПолучитьСообщенияПользователю(Истина)`: там причина отказа («Не хватает запасов…»).
- В конце — запрос остатков (`РегистрНакопления.Запасы.Остатки`), чтобы видеть, что реально списалось.
- Скрипты нумеровать по шагам (`10-nsi`, `20-docs`, `30-retail`…) и хранить в папке клиента: модель воспроизводится из них на новой демобазе.
- Файлы `.bsl` — UTF-8 с BOM (`run-code.ps1` перекодирует сам).

## Порядок модели
1. `01-probe` — что в демобазе: организации, склады, виды цен, включённые функциональные опции.
2. Справочники клиента (`10-nsi`): склады и магазины нужных типов, виды цен, товары с характеристиками и упаковками, контрагенты с договорами.
3. Документы дня (`20-docs`): установка цен → приход → перемещение → продажа опт → оплата → попытка продать без остатка → списание.
4. Розница (`30-retail`): способы оплаты, касса, смена.
5. Особенности клиента: комплекты (`40-nabor-sborka`), производство, услуги, отчёты.
6. Отчёты — смотреть глазами в интерфейсе; формирование отчётов на СКД из кода часто падает на параметрах.

## Ловушки УНФ KZ 3.0.9.3 (проверено в демобазе)
- **Счета учёта.** Новая номенклатура без счетов учёта — приходная накладная не проводится («Не заполнен счет дебета»). Копировать счета (запасов, затрат, доходов, метод оценки, категория, направление) с демо-товара; у розничного склада — счета учёта в рознице и наценки с демо-магазина.
- **Договор создаётся сам.** При записи контрагента программа сама заводит договор с основным видом цен. Свой договор скрипт не создаст (уже есть) — вид цен нужно выставить в существующем договоре. На внедрении — то же: вид цен по умолчанию или правка договора.
- **Цена за упаковку** пересчитывается сама: цена за коробку → за штуку. При получении цены по виду цен коэффициент передавать 1, иначе двойное умножение.
- **Контроль остатков** — две отдельные константы: `КонтролироватьОстаткиПриПроведении` и `КонтролироватьОстаткиПриПробитииЧековККМ`. В демо обе включены.
- **Сборка на складе типа «Розница» не проводится** («не хватает остатка по учету запасов и затрат»). Собирать заранее — на складе типа «Склад» и перемещать; собирать при покупателе — наборы (`ЭтоНабор`, состав в регистре `СоставНаборов`, в чеке состав меняется, списывается по факту, работает на рознице).
- **Чеки через РМК** без подключённой онлайн-кассы не пробить — розничную смену в модели закрываем «Отчётом о розничных продажах» по автономной кассе; безналичные оплаты — в табличной части `БезналичнаяОплата` со способом оплаты.
- **Деньги по способам оплаты** разнесены по отчётам: касса — «Денежные средства», выручка касс — «Денежные средства в кассах ККМ», карты и QR раздельно — «Оплата платёжными картами».
- **Первая организация демобазы** — не обязательно та, что нужна; явно найти организацию по имени.
- Демо-данные в модели остаются (чужие организации, документы) — клиенту модель не показываем; для демодоступа клиенту — чистая база из `1Cv8.cf` с данными клиента.

## Как искать в коде (выгрузка XML)
| Что ищем | Где |
|---|---|
| Какие возможности есть и включаются | `Constants\` — функциональные опции (`ФункциональнаяОпция…`, `Использовать…`, `Вести…`); синоним в `<v8:content>` |
| Реквизиты и табличные части документа | `Documents\<Имя>.xml` |
| Что уходит в обмен с Бухгалтерией | `ExchangePlans\ОбменУправлениеНебольшойФирмойБухгалтерия30\Ext\Content.xml` |
| Оборудование и драйверы (кассы, эквайринг) | `Catalogs\ДрайверыОборудования\Ext\Predefined.xml` |
| Казахстанские доработки | объекты с префиксом `УНФ_РК_` (например, интеграция с НКТ, панель онлайн-кассы) |
| Логика формы, команды | `<Объект>\Forms\<Форма>\Ext\Form\Module.bsl` |
| Чего в конфигурации нет | поиск по имени объекта или термину по всей выгрузке; ничего не нашлось — так и пишем: «в конфигурации нет» [код] |

Поиск — через Grep/Select-String по каталогу выгрузки, сначала по именам файлов, потом по содержимому. Тяжёлые выборки из базы не делать — код читать из XML.
