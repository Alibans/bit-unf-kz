# Правила и нюансы, которые меняют предложение

Пометки: **[правило]** — правило отдела; **[код]** — проверено по коду УНФ KZ 3.0.9.3; **[база]** — проверено в демобазе; **[вывод]** — рассуждение, проверить на своём случае.

## Бухгалтерия и разделение учёта
Внедряем торговый продукт — оперативный (торговый) учёт переезжает в него; в Бухгалтерии остаётся регламентированный учёт.

| Ситуация | Что это меняет | |
|---|---|---|
| Бухгалтерии нет, ЭСФ и налоговая отчётность из программы не нужны | Бухгалтерия не нужна, УНФ работает самостоятельно | [правило] |
| Бухгалтерии нет, но нужны ЭСФ или отчётность из программы | Бухгалтерия + обмен. Обмен входит в модель: показываем процесс в УНФ и как он отразится в Бухгалтерии | [правило] |
| Бухгалтерия есть | Спросить, доработана ли; какие процессы переезжают в УНФ и насколько они типовые. Потенциально — обследование | [правило] |
| Обмен УНФ ↔ БК | Из коробки работает плохо. Сверхтиповые работы по обмену заранее не закладываем — выявляем и оцениваем на моделировании | [правило] |
| Бухгалтерия доработана | Доработанные реквизиты и объекты типовой обмен не переносит — правила обмена дорабатывать, это в модель и в оценку | [вывод] |
| Ведущая база | Решить, где заводятся номенклатура, контрагенты, договоры; где ведутся банк и касса; кто вводит поступления — от этого зависит, что грузит обмен и кто что делает руками | [вывод] |
| ЭСФ | В УНФ KZ ЭСФ выписываются, есть прямой обмен с ИС ЭСФ, но документ ЭСФ в обмен с БК не входит — решить, из какой базы выписываем, чтобы не было двух источников | [код] план обмена с БК 3.0 |
| СНТ, виртуальный склад | В УНФ KZ их нет, в БК 3.0 есть. Работает с СНТ — Бухгалтерия обязательна | [код] |
| Зарплата в УНФ | Начисление зарплаты в обмен с БК не входит; зарплату для налогов считать в БК или ЗУП | [код] |
| Переход с работающей Бухгалтерии | Начальные остатки — из Бухгалтерии на дату перехода; беспорядок там = беспорядок в стартовых остатках | [вывод] |
| Характеристики и упаковки | В Бухгалтерии характеристик нет — на модели решить, как бухгалтер хочет видеть товары | [вывод] |
| Бухгалтер на аутсорсе (своя база, свой сервер, Фреш) | Обмен между площадками: способ передачи, кто отвечает за обмен и обновления у бухгалтера, его согласие | [вывод] |
| Обновления | Обе базы обновлять вместе, на обе — ИТС | [вывод] |

## Продукт, лицензии, где работает база
| Ситуация | Что это меняет | |
|---|---|---|
| Версия | Только ПРОФ | [правило] |
| Больше 5 одновременных пользователей (лучше уже от 4) | SQL обязательно: сервер 1С + SQL, лицензия на сервер 1С и железо — в КП. Блокировки и торможение файловой базы — тоже повод | [правило] |
| Наш хостинг | На хостинге держим только головную базу (офис). Розничные точки не должны зависеть от интернета: база точки локально, связь с головой — РИБ. На точке обычно один пользователь — файловой базы хватает | [правило] |
| Несколько касс на точке | Кассе не нужно видеть остатки других — РИБ на этом месте. Несколько касс в одном помещении видят остатки друг друга — РИБ на одной кассе, остальные подключаются к ней по локальной сети. Либо хороший сервер и все кассы работают с ним — тогда зависимость от сети есть, риск берёт клиент (зафиксировать письменно) | [правило] |
| РИБ | На каждую базу — своя основная поставка (дороже клиентских лицензий). Сказать клиенту на встрече, заложить в КП. В конфигурации РИБ полный и с фильтром | [правило]; [код] |
| 1С:Фреш | Доработки только расширениями в безопасном режиме и через аудит 1С; РИБ нет — автономная работа; обмен с БК — внутри сервиса | [код] опции; [вывод] |

| Маркировка | Поддерживается; 2D-сканеры, онлайн-касса, регистрация в системе маркировки | [код] |
