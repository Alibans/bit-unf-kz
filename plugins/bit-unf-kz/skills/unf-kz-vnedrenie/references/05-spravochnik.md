# Свой справочник процессов УНФ KZ

Справочник процессов по участкам каждый собирает сам — на своей демобазе и своей выгрузке конфигурации, под свой релиз. Скилл даёт метод, а не готовые ответы.

## Где хранить
Папка `references/процессы/` рядом с этим файлом (или своя папка проекта), один файл на участок: `01-товары.md`, `02-продажи.md`, `03-розница-рмк.md`, `04-закупки.md`, `05-склад.md`, `06-деньги.md`, `07-расчёты.md`, `08-производство.md`, `09-услуги.md`, `10-обмен-с-бк.md`, `11-персонал.md`, `20-диагностика.md` (симптом → причина → что проверить → что сделать).

## Как заполнять
1. Перечень возможностей участка — по функциональным опциям (`Constants\`) и документам (`Documents\`) выгрузки.
2. Для каждой возможности — смысл и цепочка документов, где включается, ловушки.
3. Каждое утверждение — с пометкой и датой: [код] — нашёл в выгрузке; [база] — провёл в демобазе; [ИТС] — из материалов ИТС, в коде не проверено (использовать с оговоркой).
4. Новое, найденное на модели клиента (ловушка, ограничение, обходной путь), — сразу в файл участка с пометкой [база].
5. Нашёл расхождение со справочником — исправить, поставить новую пометку и дату.
6. Клиентские данные в справочник не попадают — только как устроена программа.

## Чем проверять
- Код — `references/03-model.md`, «Как искать в коде».
- Поведение — скриптом через `scripts/run-code.ps1` в своей демобазе (образцы — `scripts/model-examples/`).
- Методические материалы — its.1c.kz (раздел УНФ для Казахстана); статьи ИТС часто написаны под старые релизы — истина в коде своего релиза.
